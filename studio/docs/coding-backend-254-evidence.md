Process loss/unconfirmed drain revoke the workflow credential but preserve the hold, and subsequent idle ticks cannot unload it. The child process is a real owned framed-transport **fault fixture**, not native Mimir.
- Added `tests/test_coding_execution_boundary.py`: both authenticated HTTP routers coexist. Coding acceptance/refusal remains native, refusal cannot fall back to general chat, and `/v1/chat/completions` succeeds independently even when the coding runtime is unusable. Existing subject/operation/saved-workspace assertions remain; no assertion was weakened and no new exclusion/skip was added.

All 33 tests in that file plus the recovered audio-owner case subsequently passed (34 total).
- Parent real-browser integration subsequently reproduced production error-mapping defects: native `unsupported_command`, `invalid_answer` and `stale_answer` were presented as HTTP 502 instead of client refusals. Added `test_unsupported_native_command_is_a_client_refusal_not_a_gateway_failure` and expanded the existing no-retry question test with the exact native codes (fail 502 versus 400/409 before the fix), then mapped those exact codes to HTTP 400/400/409. Unknown commands still cannot fall back to model execution; answers are attempted once with unchanged identities and actionable native messages. Reproductions: `unsupported-command-reproduction.log`, `question-error-reproduction.log`; final full coding rerun: `coding-parent-final.log` (293 passed). No backend execution/lifecycle ownership semantics were changed.

### Environment failures and recovery (not production failures)

The first broader run had a lifecycle collection error (missing `typer`), 13 ordinary-chat/auth failures from missing `markdown_it`, `typer`, `diceware`, and `fastmcp`, and four multi-account collection errors also requiring CPU `torch`. Installed ordinary declared dependencies and a CPU-only torch wheel into the task venv, then reran. The lifecycle and all 742 ordinary-chat/auth/folder tests passed without changing their assertions. Original failures are retained under `initial-regressions/`; installation output is `install*.log`.

The completed 32-part multi-account run then exposed 230 optional audio/RAG setup failures (missing PyAV/sqlite-vec) and two media construction-barrier failures. A separate task-owned `.verification/backend-regression-venv` was copied from the ready venv; optional `av`, `sqlite-vec`, and the repository's `transformers==5.5.0` pin were installed **only there**. The parent's ready `.verification/backend-venv` was not modified. Recovery reran all 232 failed IDs (230 passed, one remaining missing-Transformers audio refusal, one hardware-probe barrier failure), followed by 34/34 passing final audio/media tests after dependency and CPU-fixture recovery. Failures and retries remain preserved, including `multi-account-environment-failures.json`, `multi-account-failed-nodes.json`, installation logs, and the per-test reconciled ledger.

The pre-fix serial multi-account run was intentionally terminated after the 22-route completeness defect was reproduced and fixed. A 180-second targeted serial authorization run and an overlapping 180-second coding rerun timed out without assertion failures; the first four-part attempt was intentionally superseded by a bounded 32-part run. These incomplete attempts are **not pass claims** (`multi-account-pre-fix-cancelled.log`, `matrix-coding.log`, `coding-after-matrix.log`, `four-part-cancelled/`). The host reported 192 logical CPUs and heavy existing CPU load; full partitions cap BLAS/OpenMP threads to one, have independent basetemps, and include every collected test ID exactly once. The final non-overloaded coding rerun passed all 290 tests. Suite totals overlap (for example coding protection and shared-history cases); do not sum the rows as unique-test counts.
